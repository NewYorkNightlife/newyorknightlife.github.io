# NYNightlife.com

Know before you go: dress code, age, cover and how to get in for NYC bars and clubs, with sources
and the date each fact was checked. Static HTML on GitHub Pages. Live site: https://nynightlife.com

## How it's built (Oct 2026 rebuild)

- `_build/` holds the generator and the data. GitHub Pages skips underscore folders, so none of it is served.
  - `_build/data/venues/*.json`: one file per venue. Every fact has a status (confirmed / likely /
    unconfirmed / unknown) and its sources. The `chat` block holds Nyla's tags and nicknames.
  - `_build/data/playbooks/*.json`: group-night pages, priced per person.
  - `build.py` and `pages.py` write the pages. `nyla.py` writes `data/venues.json` for the chatbot, from the same venues, hours, guides, and events feed as the pages.
  - `concierge.js` is the source for `js/concierge.js` (Nyla, the chat helper).
  - `nyla-voice.js` is the source for `js/nyla-voice.js`: hold Nyla (or tap the mic) to ask out loud; she answers out loud. Browser-only Web Speech API, no server, no keys. Tests: `node _build/test_nyla_voice.js .`
  - `site.css` is the source for `css/site.css`. Fonts are self-hosted in `/fonts/` (SIL OFL).
  - `make_images.py` turns the masters in `_build/img/` into the responsive WebP/JPEG set.
  - `make_og.py` draws the 1200x630 share card for every page, from facts already on the page.
- Rebuild: `python _build/build.py`, then `python _build/test_html.py`, `python _build/test_nyla_data.py`, and `node _build/test_nyla.js .` (HTML, JSON-LD, Nyla's file vs the events feed and guides, links, and Nyla's answer tests). Daily build treats Nyla's phrase checks as a warning (`--intents`) so a data-dependent miss cannot block an otherwise good deploy. A stale or incomplete Nyla file still fails (`test_nyla_data.py`). Broken links still fail (`--links`).
  - After adding or replacing a photo, run `python _build/make_images.py` and
    `python _build/make_og.py` first. `build.py` fails if a page references a file that is missing.
  - `sitemap.xml` is generated by `build.py`. Each `lastmod` is the newest of the git date of that page's content inputs and, for pages rebuilt from the event feed, the day the rendered listings changed (`_build/freshness.py`). The same date is the page's `dateModified` and its visible Updated line. A rebuild that changes nothing leaves the date alone.
  - Venues we hold no licensed photograph of get a cover drawn in CSS, never a stand-in photo.
- What's on (Nov 2026): `python _build/events.py` writes `_build/data/events/latest.json` from NYC Open Data (parks and permitted events). Ticketmaster Discovery (music, comedy, theatre, nightlife) runs only when `TICKETMASTER_API_KEY` is set; Viator search runs only when `VIATOR_API_KEY` is set. A failed source keeps its last good rows. Ticketmaster rows older than 36 hours are dropped. Ticketmaster images are hotlinked beside that event and are not saved in the repo; the ticket link is the event URL. The snapshot is replaced atomically and rows sort by start, then id, so running the fetch twice is safe. `.github/workflows/daily-build.yml` fetches, builds, tests, and deploys with GitHub Pages actions (no commit) at 09:17 and 14:41 UTC, and again after each successful Live data run. Those times are off the hour because a single 10:00 UTC cron was still unpublished in the middle of the New York day. `python _build/build.py` still writes the HTML that a branch deploy serves, including `data/events.json`, the week snapshot. The baked date on `/` and `/tonight/` is the New York night of that build and is the no-JS fallback. `js/tonight.js` rewrites the date, the counts, and the cards for the visitor's current America/New_York night (5pm to 5am; after midnight and before 5am, the previous evening). `Updated` stays the feed's own timestamp.
- Live data (Oct 2026): `.github/workflows/live.yml` runs `_build/live.py` four times a day. It fetches the NWS
  forecast, nightlife headlines (only feeds marked `terms: "ok"` in `FEEDS`) and new NYS liquor licenses, and
  publishes `data/live/*.json` to the **`live-data` branch** (main only takes pull requests). `js/live.js` reads
  them from raw.githubusercontent.com, falling back to the copy in `/data/live/`. Never commit `data/live/` by hand.
  A successful Live data run starts Daily build, which is what republishes the dated pages. The live-data job itself does not rebuild HTML.
  A source failing 4 runs in a row opens a "Live data job failed" issue; a good run closes it.
  Tests: `python _build/test_live.py`. Weekly hours for "open tonight" live in each venue's `hours.week`
  (`_build/add_week_hours.py`). The newsletter form appears once `_build/config.json` has `kit_form_action`.
- Pages that were retired in the rebuild are listed in `_build/REMOVED-2026-10.txt`. They can be restored
  from git history.

Never commit secrets: everything in this repo is public.
